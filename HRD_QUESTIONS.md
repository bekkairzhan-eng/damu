## Открытые вопросы

### Навыки и подтверждение

1. [ ] **Роль «Руководитель» для подтверждения уровня 4** — нужно завести как отдельную роль в Damu (сейчас только employee/hr/admin), привязать к оргструктуре («кто чей руководитель») и определить источник этих данных (HRMS?).
2. [ ] **Механика подтверждения через BILIM/TestLab** — точный триггер подтверждения уровня 1–2 в BILIM (по факту завершения курса? по проходному баллу теста?) и порог зачёта уровня 3 в TestLab — не описаны, уточнить отдельно с командами этих систем.
3. [ ] **Кумулятивность уровней навыка** — если BILIM подтверждает сотруднику уровень «Средний» напрямую (например, курс/тест рассчитан сразу на средний уровень, без отдельного прохождения курса «Базовый»), нужно ли автоматически считать «Базовый» тоже подтверждённым? Аналогично для TestLab (уровень 3) — засчитывается ли автоматически «Средний», если по нему не было отдельного курса? Сейчас в прототипе `employee_skill` хранит только одно число `current_level`, и шкала на UI закрашивается кумулятивно (все уровни от 1 до текущего) — то есть уровень де-факто трактуется как монотонный прогресс без отдельного подтверждения на каждую ступень. Нужно решение бизнеса: соответствует ли это реальной логике BILIM/TestLab, или подтверждение каждого уровня — отдельное событие, и `current_level` должен вычисляться как «максимум из отдельно подтверждённых уровней», а не просто перезаписываться сверху.
4. [ ] **Статусы «не подтверждён»/«отклонён»** — навыки в этих статусах участвуют ли в чём-то кроме компонента рейтинга «Подтверждённые навыки» (например, в проверке готовности плана к аттестации)?
5. [ ] **Подлинность сертификатов** — кто проверяет сертификаты, добавленные вручную (HR или сотрудником)? Достаточно ли загрузки скана, или нужна отдельная проверка?

## Закрытые вопросы (лог решений)

- [x] Официальные названия должностей — из 1С: Foreman A/B/C, Site Manager, Deputy PM, Project Manager, Директор Управления, Генеральный Директор.
- [x] Профиль сотрудника — полностью из HRMS (ФИО, фото, должность, стаж, подразделение).
- [x] Корпоративная активность — источник HRMS, 5 фиксированных показателей по 1 баллу.
- [x] Нужен ли публичный рейтинг / риск демотивации — **решено:** рейтинг локальный по должности (сравнение только со своим грейдом в своей компании/кластере) + общий балл доступен по кнопке «Показать общий рейтинг».
- [x] Как сотрудник заявляет свой уровень навыка — **решено 23.07.2026 (Дильдар):** никак сам не заявляет ни один уровень; 1–2 подтверждает BILIM, 3 — TestLab, 4 — эксперт/руководитель через BPM, комментарий обязателен и при подтверждении, и при отклонении. См. [TASKS.md](TASKS.md#логика-подтверждения-навыков-по-уровням).
- [x] Кто создаёт карьерный план — **решено:** авто-создаётся при первом входе (цель = следующая ступень основной ветки), сотрудник может сменить цель сам через карьерную карту.
- [x] Кто инициирует аттестацию — **решено:** сотрудник, кнопка доступна от 85% выполнения плана.
- [x] «План развития на основе оценки» — что за оценка — **решено:** это тот же карьерный план, дополненный комментариями HR по непройденным навыкам последней аттестации. Подробности — [TASKS.md](TASKS.md#результат-аттестации-что-вносит-hr).
- [x] Где хранятся данные обучения и сертификатов — **решено:** LMS (BILIM) + ручной ввод HR, отображаются в «Профиль опыта» с разбивкой по кварталам.
- [x] Кто принимает финальное решение о повышении — **решено:** офлайн-процесс HR/руководства, вне системы; Damu только показывает статус «на скамейке» после успешной аттестации.
- [x] Аттестация — детальный флоу в BPM (участники добавляются HR в BPM, встреча назначается офлайн через Outlook, результат вносится в существующем экране Damu).
- [x] Заявка на обучение — уже существует в BPM; три источника подачи (сотрудник самостоятельно / HR за сотрудника); сверка `pending`-заявок с LMS по крону раз в сутки; ручное добавление сертификата HR-ом с привязкой к существующей заявке.
- [x] Точка входа для самостоятельной подачи заявки на обучение (31.07.2026) — кнопка «+ Записаться на курс» в «Профиль опыта» → «Программы обучения», не привязана к истечению сертификата.
- [x] Выгрузка отчётов в Excel из HR-панели (предложение Алсу, встреча 23.07.2026) — рассмотрим, но **не в MVP**.
- [x] Проекты сотрудника — новые проекты идут через SuperApp (без апрува HR, когда интеграция готова); проекты, введённые вручную до этого, подтверждает HR поштучно через новую сущность в UnityBPM (детали флоу — открытые пункты №17–20 выше).
- [x] HR/менеджер в MVP не нужен как отдельный экран.
- [x] Назначение в обход навыков (сотрудник получил должность без выполнения всех требований) — система всё равно создаёт активный план с gap-анализом; аттестация запрашивается в обычном порядке.
- [x] Навыки вне карьерного трека (31.07.2026) — сотрудник может добавить в профиль любой навык каталога, подтверждается тем же пайплайном (BILIM/TestLab/эксперт), без исключений.
- [x] Исключение навыка из «Мои навыки» (31.07.2026) — доступно только пока уровень не выставлен вообще; как только выставлен любой уровень — исключить нельзя ни при каком статусе; целевые навыки исключить нельзя никогда.
- [x] Порог готовности для запроса аттестации — **85%** выполнения плана.
- [x] Мобильная версия — обязательна в MVP (WebView в BI Life).
- [x] Тёмная тема — не блокер MVP, полноценная реализация (без CSS-filter хака) — post-MVP итерация.
- [x] Подтверждение навыков по матрице через UnityBPM (РП/тех.специалист) — **пересмотрено 23.07.2026**, см. открытый вопрос №1–2 выше и [TASKS.md](TASKS.md#логика-подтверждения-навыков-по-уровням): актуальна только для уровня 4.
